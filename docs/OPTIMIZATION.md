## P0 — 提交前必做

### P0-1 自定义域名（杀掉 MetaMask「恶意网站」警告）

- **现状**：`*.vercel.app` 随机子域被 Blockaid 判为恶意，demo 体验崩。
- **做法**：在 Vercel 绑定自定义域名；用 `app.你的域名` 访问。
- **验收**：MetaMask 连接/交易不再弹安全警告。
- **影响**：UX 20% + Presentation 15%。工作量：小（需一个域名）。

### P0-2 一句话定位重写

- **现状**：「不必相信同一个未来…」太诗意，评委 get 不到机制。
- **做法**：首屏改为
  `1 Up + 1 Down = 1 抵押品。两个判断相反的人，可以不赌输赢，而是把对赌变成共同出资。`
- **验收**：非技术人员 30 秒内能复述机制，并能说出与普通预测市场的差别。
- **影响**：Innovation 20%。工作量：小。

### P0-3 合约源码验证（Somnia 浏览器）

- **现状**：`CommonGroundCampaign` 未验证，影响信任且是安全警告来源之一。
- **做法**：`forge verify-contract` 或浏览器提交源码+构造参数。
- **验收**：浏览器上合约页显示已验证源码与 ABI。
- **影响**：Technical 25% + 可信度。工作量：小。

### P0-4 一键资助 + 进度反馈

- **现状**：approve → mintSet → setOperator → deposit → activateBase 五步散落，用户不知道在干嘛。
- **做法**：合并为「资助基础任务」一键流程，逐步显示 approve / mint / deposit / merge 状态与 tx hash。
- **验收**：一次点击走完整流程；每步有进行中/成功/失败状态；失败可重试。
- **影响**：UX 20%。工作量：中。

### P0-5 交付证据页（补上产品闭环）

- **现状**：界面只有预算与任务状态，看不到「交付了什么」。
- **做法**：任务详情页展示 artifact（uri + hash）、verifier 决策与理由、付款状态与 tx。
- **验收**：任一任务能追溯到「执行者交付物 + 验收结果 + 是否付款」。
- **影响**：UX 20% + Business 20%（这是「有交付责任」最直接的证据）。工作量：中。

### P0-6 两分钟 demo 视频

- **做法**：20 秒定位（反直觉对比）+ 真机操作（资助 → 合并 → 结算 → bonus 触发/跳过）+ 合约地址收尾。
- **验收**：不依赖解说也能看懂「两个相反判断的人共同资助了一件事」。
- **影响**：Presentation 15%。工作量：中。

## P1 — 强差异化（拉开分差）

### P1-1 Somnia Reactivity 自动触发

- **现状**：结算推进靠 worker 轮询。
- **做法**：部署 Reactivity handler，订阅市场 `Resolved`/`Voided` 事件，链上自动调用 `syncMarketAndBonus`。
- **验收**：不依赖任何 off-chain 进程，市场结算后 bonus 自动判定。
- **影响**：Technical 25% + 生态分（证明「为 Somnia 而生」）。工作量：中高。

### P1-2 实时事件流

- **做法**：前端订阅链上事件（替代 10s 轮询），状态变化即时反映。
- **影响**：UX 20%。工作量：中。

### P1-3 Faucet 引导

- **做法**：检测 STT / tUSDC 余额不足时，一键领测试币或提示领取入口。
- **影响**：UX 20%（新用户最大卡点）。工作量：小。

### P1-4 安全与边界测试

- **范围**：重入、精度（6 vs 18 decimals）、错误市场/结果 id、旧 planHash 重放、并发激活。
- **影响**：Technical 25%。工作量：中。

### P1-5 具体商业用例

- **做法**：README 首屏写一个具体场景，例如「协议发起事件市场：配对部分无条件资助安全审计；里程碑达成才追加渗透测试」。
- **影响**：Business 20%。工作量：小。

### P1-6 错误处理与加载态

- **范围**：交易失败、用户拒签、网络错误、余额不足，全部有清晰反馈与恢复路径。
- **影响**：UX 20% + 成熟度。工作量：中。

## P2 — 成熟产品（黑客松之后）

### P2-1 多计划 / 多市场

- 现状一个 campaign 绑死一个市场；改为 Plan registry + factory，支持并发计划。

### P2-2 精确退款模型

- 现状按 points 比例近似；改为按份额精确清算（含手续费与余额差）。

### P2-3 计划创建流程

- 允许任意发起人配置市场、任务、执行者、验收者、期限并发布，脱离「部署合约即创建」。

### P2-4 监控与告警

- worker 健康、Reactivity 订阅余额、异常事件、资金流对账。

### P2-5 CI/CD

- `forge test` + `web build` + 合约验证自动化。

### P2-6 主网配置切换

- 主网 USDso 18 decimals vs 测试网 6，配置化避免精度事故。

### P2-7 安全审计与权限复核

- 外部审计、执行者/验收者权限模型、退款与清算的形式化验证。

---

## 建议执行顺序

1. P0-1（域名）→ P0-2（定位）→ P0-3（验证）—— 快速见效，先止血。
2. P0-4（一键资助）→ P0-5（证据页）—— 补 UX 与闭环。
3. P1-1（Reactivity）—— 最强技术差异化。
4. P0-6（demo 视频）—— 最后统一录制。
5. 其余 P1 → P2 按时间投入。
